# CRPA hardware: 12-element all-band GNSS anti-jam array

KiCad 10 design files for the 12-element polarization-diverse CRPA simulated in the
parent folder. All files are **generated by scripts**, so change the generator scripts
and re-run them rather than editing the boards by hand.

| Status | Board | Files |
|---|---|---|
| Layout done, DRC 0 errors, Gerbers exported | Element feed board, circular (RHCP/LHCP selectable) | `antenna/feed_circular/` |
| Layout done, DRC 0 errors, Gerbers exported | Element feed board, linear | `antenna/feed_linear/` |
| Layout done, DRC 0 errors, Gerbers exported | Lower patch carrier (1164-1300 MHz) | `antenna/patch_lower/` |
| Layout done, DRC 0 errors, Gerbers exported | Upper patch carrier (1559-1610 MHz) | `antenna/patch_upper/` |
| Outline and holes, DXF exported | Aluminium array ground plate | `antenna/array_plate/` |
| Schematic, ERC 0 errors / 0 warnings | 12-channel RF front-end | `rf_frontend/` |
| Schematic, ERC 0 errors / 0 warnings | RFSoC carrier + u-blox ZED-X20P | `dsp_gnss/` |

> **Rev B (compact, Rogers TMM3 elements, 320 x 395 mm array) is in
> [antenna_tmm/](antenna_tmm/README.md) and supersedes the rev A antenna below.**
> The front-end and DSP/GNSS schematics are shared by both revisions.

> **Before ordering anything, read the "Not done yet / must verify" section.** The
> antenna dimensions come from closed-form models and must be tuned in a full-wave EM
> solver. Several part numbers are candidates whose pinouts must be checked.

## 1. System architecture

```
 12 antenna elements                     RF front-end (x12)                     RFSoC carrier
 -------------------                     ------------------                     -------------
 3x RHCP   (zenith)  -\                                                         ZU49DR SOM (iWave G42M)
 3x linear (zenith)    >-- SMA --> limiter -> 20dB coupler -> LNA -> BPF ->       RF-ADC x12 @ 2.0 GSPS
 3x monopole (zenith)  |                          ^         gain block -> SMA --> (2nd Nyquist 1.0-2.0 GHz)
 3x LHCP/RHCP (tilted to jammer, el 10 deg) -/     |                                    |
                                                  | cal tone/noise          STAP beamformer in PL
                                     1:12 split <-+---------- SMA <-------- RF-DAC1 (calibration)
                                                                                    |
                                     u-blox ZED-X20P <-- 10 dB pad <-- LPF <-- RF-DAC0 (clean L-band RF)
                                     (all-band GNSS)                     \---- RF-DAC2 -> AJ RF OUT (SMA)
```

- **Direct RF sampling.** The RF-ADCs sample at 2.0 GSPS, so 1.0-2.0 GHz is the
  second Nyquist zone. It contains every GNSS band from 1164 to 1610 MHz with margin, so
  no mixers and no local oscillators are needed.
- **Why the RF-DAC.** The ZED-X20P only accepts RF, so the beamformed signal is
  re-synthesized at L-band by an RF-DAC at about 6.4 GSPS. Commercial anti-jam units feed
  COTS receivers the same way. The few-microsecond latency appears to the receiver as a
  common clock bias and does not affect the position solution.
- **Channel equalization.** RF-DAC1 injects a calibration signal through the 20 dB
  couplers. The FPGA measures every chain and applies per-channel FIR equalizers. The
  simulation showed that without equalization the array collapses after about 6 jammers.

## 2. Antenna element

Air-spaced, dual-band stacked patch, built from three PCBs and nylon M3 standoffs:

```
  upper patch board   FR4 0.8 mm, square patch on the BOTTOM side   81.9 mm   parasitic, 1559-1610 MHz
  ---- 6 mm air (nylon standoffs) ----
  lower patch board   FR4 0.8 mm, square patch on the BOTTOM side  105.5 mm   probe fed, 1164-1300 MHz
  ---- 9 mm air (nylon standoffs), 2 probes of 16 AWG copper wire ----
  feed board          RO4350B 0.762 mm: F.Cu = ground plane, B.Cu = microstrip + printed hybrid + SMA
  ---- >= 6 mm gap to the aluminium plate (keeps the microstrip impedance) ----
  array plate         6061-T6, 3 mm; SMA passes through an 8.4 mm hole
```

| Parameter | Value | Source |
|---|---|---|
| Board size | 124 x 124 mm (element pitch 125 mm) | |
| Probe offset from patch centre | 25.3 mm, at +x and at +y (screen-up) | TL model |
| Probe reactance at 1.23 GHz | about 57 ohm, so C1 and C2 can take ~2.2 pF to cancel it | `design_calc.py` |
| Hybrid | 2-section branch line: Za 115 ohm (0.28 mm), Zb 40 ohm (2.37 mm), Zc 36 ohm (2.77 mm) | optimized over 1164-1610 MHz |
| Hybrid return loss / isolation | >= 22 dB / >= 22.7 dB (ideal lines) | `hybrid_response.png` |
| Hybrid amplitude / phase error | 0.65 dB / 0.2 deg, about 0.65 dB axial ratio | |

### Choosing RHCP or LHCP (feed_circular)

| Polarization | R2 (series, port 1) | R1 (shunt, port 1) | R4 (series, port 4) | R3 (shunt, port 4) |
|---|---|---|---|---|
| **RHCP** | 0 ohm | DNP | DNP | 49.9 ohm |
| **LHCP** | DNP | 49.9 ohm | 0 ohm | DNP |

Use 0603 thin-film resistors. C1 and C2 are the probe-tuning positions: fit 0 ohm until
the element has been measured.

> **Recommendation for the 3 tilted modules:** build them as **RHCP**. On the real
> hardware geometry (`run_hardware_array.py`), tilted LHCP modules lose satellites
> against an 80-90 dB RHCP jammer (power inversion: 2/9 and 0/9 tracked). Tilted RHCP
> modules keep 9/9. The boards support both settings, so this choice costs nothing.

### Linear elements

`feed_linear` is the same stack with a single probe. The E-field is along the probe
axis, which the silkscreen marks. The three H modules are rotated 0, 60 and 120 deg on
the plate. The three vertical elements are 50-52 mm brass rods (6.35 mm diameter) on SMA
bulkheads, a fat monopole for bandwidth. Tune the rod length on a VNA.

### Array plate (`array_plate/array_plate.dxf`, `element_positions.json`)

```
              JAMMER SIDE  (az 0, boresight el 10 deg)
        [L-tilt]        [L-tilt]        [L-tilt]      <- brackets, 80 deg from horizontal
         R  (-125,-125)  H 0deg (0,-125)  V (125,-125)
         V  (-125,0)     R (0,0) REF     H 60deg (125,0)
         H 120deg(-125,125) V (0,125)    R (125,125)
```

The mixed layout means no row or column repeats an element type. The centre RHCP
element is the power-inversion reference. The tilted-module bracket is a 3 mm aluminium
angle bent to 80 deg, with two M4 holes into the plate and the module's four M3 holes on
the tilted face.

## 3. RF front-end (`rf_frontend/`)

| Stage | Candidate part (VERIFY) | Purpose |
|---|---|---|
| Limiter | PIN limiter, about +40 dBm survivable | Survive a close high-power jammer |
| 20 dB coupler | 1.1-1.7 GHz directional coupler | Calibration injection |
| LNA | Infineon BGA855N6 (1164-1615 MHz GNSS LNA) | Sets the noise figure |
| Band-pass | 1150-1620 MHz | Anti-alias for the 2nd Nyquist zone, rejects 900 MHz / 2.4 GHz C2 links |
| Gain block | Mini-Circuits PGA-103+, choke-biased from 5 V | Drives the ADC |
| Cal splitter | 1:4 then 3x 1:4 (spare output terminated) | 12 calibration feeds |

**Rough link budget (estimate, verify with datasheets):** gain about 32 dB, noise
figure about 1.6 dB.
- The noise floor at the ADC is about -141 dBm/Hz, roughly 8 dB above the RF-ADC's own
  noise, so the ADC adds about 0.6 dB.
- With about 6 dB back-off from the ADC's +1 dBm full scale, the largest jammer the chain
  handles is roughly **-40 dBm at each element**.
- A SkyShield-class jammer (100 W, 13 dBi, all power in one GNSS band) gives about
  -53 dBm at 10 km and about -39 dBm at 2 km.
- **Recommended addition:** a 0-31.5 dB digital step attenuator per channel, under AGC
  from the FPGA. It adds about 30 dB of headroom against close-in jammers.

## 4. RFSoC carrier and GNSS receiver (`dsp_gnss/`)

- **SOM:** iWave iW-RainboW-G42M, ZU49DR (16 RF-ADCs at 2.5 GSPS, 16 RF-DACs at
  10 GSPS, 2 x 400-pin board-to-board connectors).
  - The SOM symbol is functional.
  - Every pin must be mapped to the iWave pinout (you need iWave's datasheet and
    carrier design guide).
  - Clocking (RF PLL, SYSREF) must follow iWave's reference carrier.
- **GNSS receiver:** u-blox **ZED-X20P**, all-band L1/L2/L5/L6 (GPS, Galileo, GLONASS,
  BeiDou, QZSS, NavIC). It uses KiCad's reviewed `RF_GPS:ZED-F9P` symbol and
  `RF_GPS:ublox_ZED` footprint, because u-blox states the X20 is pin-to-pin compatible
  with the F9.
  - **Verify every pin against the ZED-X20P datasheet.** SparkFun reports at least one
    pin whose function changed.
  - VCC_RF and the antenna-supervisor pins are left unconnected: the RF comes from the
    DAC, so there is no active antenna to power.
- **Interfaces:**
  - SOM UART to ZED UART1.
  - ZED TIMEPULSE to the SOM's PPS input and a PPS SMA.
  - USB-C for u-center.
  - UART2/I2C header for RTCM corrections.
  - SMA outputs: AJ RF OUT, CAL OUT and 10 MHz REF OUT.
- **Power:** 12 V in. A buck converter makes 5 V for the front-end and the LDO, and a
  low-noise LDO makes 3.3 V for the GNSS receiver and the clock.

## 5. Not done yet / must verify

1. **EM simulation of the element (required).** Model the patch stack, probes and
   hybrid in openEMS, CST or HFSS. Tune h1, h2, patch sizes, probe offset, C1/C2 and the
   hybrid lengths (T-junction parasitics are not modelled) until:
   - |S11| < -10 dB in both bands,
   - axial ratio < 3 dB at boresight,
   - gain at 10 deg elevation is acceptable.

   Then change `design_params.json` and re-run `gen_boards.py`.
2. **Mutual coupling and pitch.** The 125 mm pitch is forced by the 105 mm air-patch
   size. It is 0.66 lambda at L1, so the array has grating lobes. Simulate the full
   array in EM, and consider dielectric loading to shrink the elements.
3. **Part numbers marked VERIFY** in the schematics: pinouts, footprints, availability,
   and export classification.
4. **PCB layout** of the front-end and carrier. Both need controlled-impedance stack-ups
   and phase-matched channel routing.
5. **Firmware:**
   - RFSoC tile configuration,
   - channel equalizer,
   - STAP weights (power inversion first, MVDR later; port `crpa_dsp.py`),
   - DAC re-synthesis,
   - AGC.
6. **Export control.** CRPA and anti-jam hardware is controlled in many jurisdictions
   (for example the US EAR/ITAR and the Wassenaar dual-use list). Check before
   manufacturing or shipping.

## 6. How to rebuild

```bash
python hardware/antenna/design_calc.py
"C:/Program Files/KiCad/10.0/bin/python.exe" hardware/antenna/gen_boards.py
powershell -File hardware/tools/check_boards.ps1 hardware/antenna
powershell -File hardware/tools/export_fab.ps1 hardware/antenna
powershell -File hardware/tools/check_schematics.ps1
python run_hardware_array.py
```

The two board scripts do the following:
- `check_boards.ps1` fills the copper zones and runs DRC; KiCad's zone filler crashes
  when run headless from Python, so it is done through kicad-cli.
- `export_fab.ps1` writes, for each board, Gerbers, an Excellon drill file, a
  pick-and-place file, renders, and a zip in `<board>/`.
